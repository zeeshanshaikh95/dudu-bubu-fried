# Deployment — DUDU BUBU FRIED CHICKEN

Two supported shapes:

* **GitHub Pages (live today)** — static storefront with a committed menu snapshot. No admin, no
  writes. Good for showing the client the design.
* **Render + MongoDB Atlas** — the real shop: live API, working admin panel, uploads.

---

## 1. GitHub Pages (static)

The workflow `.github/workflows/deploy-pages.yml` builds `client/` and publishes it on every push to
`main`.

Settings → Pages → **Source: GitHub Actions**. Then:

* `VITE_BASE` is set automatically to `/<repo>/`.
* `VITE_DEMO_CATALOGUE` defaults to `true`, so the build reads
  `client/public/demo/catalogue.json`.
* `VITE_API_URL` may be left unset for the static preview.

Regenerate the snapshot whenever the menu changes:

```shell
npm run dev:db        # terminal 1
npm run seed          # once
npm run dev:server    # terminal 2
npm run demo:catalogue
```

Commit the regenerated `client/public/demo/catalogue.json` and push.

**Live URL:** https://zeeshanshaikh95.github.io/dudu-bubu-fried/

## 2. Render + Atlas (real shop)

### Database

Create a free MongoDB Atlas cluster, a database user, and allow Render's egress (or `0.0.0.0/0` for a
first test). Copy the connection string:

```
mongodb+srv://dudu-bubu-fried:<password>@cluster0.xxxxx.mongodb.net/dudu-bubu-fried?authSource=admin&retryWrites=true&w=majority
```

### API

Render dashboard → **New + → Blueprint** → pick `zeeshanshaikh95/dudu-bubu-fried`. It reads
`render.yaml` and creates both services.

Fill these on `dudu-bubu-fried-api` → Environment:

| Variable | Value |
| `MONGODB_URI` | the Atlas string above |
| `CORS_ORIGINS` | the storefront origin, comma-separated with `http://localhost:5173` for dev |
| `PUBLIC_SITE_URL` | `https://dudu-bubu-fried-web.onrender.com` (or the custom domain) |
| `ADMIN_EMAIL` | the first admin login |
| `ADMIN_PASSWORD` | a strong one-time password (the panel forces a change) |

`JWT_SECRET` is generated by Render. `AUTO_SEED=true` creates the first admin and default settings on
boot — it is idempotent and never writes menu data.

Check `https://dudu-bubu-fried-api.onrender.com/api/health` returns `{"ok":true}`.

### Storefront

Set on `dudu-bubu-fried-web` → Environment:

| Variable | Value |
| `VITE_API_URL` | `https://dudu-bubu-fried-api.onrender.com/api` |
| `VITE_PUBLIC_SITE_URL` | the site origin |
| `VITE_DEMO_CATALOGUE` | `false` |

Deploy, then open `/admin` and sign in. Add dishes, set the WhatsApp number if it changes, and upload
her real photography.

**Free tier note:** a free Render web service sleeps after ~15 minutes idle; the first request
afterwards takes ~30s to wake. The Pages preview is unaffected.

## Custom domain

Point the domain at Render (CNAME to the web service) and add it to `CORS_ORIGINS` and
`PUBLIC_SITE_URL`. If you serve the SPA from Pages behind a custom domain instead, update `VITE_BASE`,
`VITE_PUBLIC_SITE_URL`, `robots.txt` and `sitemap.xml`.
